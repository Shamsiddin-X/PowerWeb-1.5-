# Разработка PowerWeb

[README](README.md) · [Архитектура](docs/architecture.md) · [Тестирование](docs/testing.md)

## Подготовка

1. Установите Node.js 22+ и npm.
2. Выполните `npm ci` из корня проекта. Команда устанавливает версии из `package-lock.json`.
3. Запустите `npm run dev`. Для настольного режима подготовьте Rust и системные зависимости Tauri, затем выполните `npm run tauri dev`.

`node_modules/`, `dist/`, `src-tauri/target/` и временные каталоги тестов создаются локально и исключены из Git. Не добавляйте токены, `.env`, кэш, журналы и готовые установщики в исходники.

## Изменения

- Изменяйте исходники текущих модулей; карту проекта смотрите в [архитектуре](docs/architecture.md).
- Добавляйте регрессионный сценарий для исправленного поведения. Новый `tests/*.test.ts` автоматически включается в `npm test`.
- Проверяйте входящие документы до замены открытого проекта. Сохраняйте чтение старых JSON PWB при изменении контейнера.
- Разделяйте версию приложения и формат `.pwb`. Обновляйте описание формата при изменении структуры или ограничений.
- HTML и React должны использовать общее дерево экспорта и общие ресурсы. Проверяйте, что экспорт не изменяет открытый документ.
- При изменении зависимостей обновляйте `package.json` и `package-lock.json` вместе. Используемые тестами инструменты объявляйте напрямую в `devDependencies`.

## Перед pull request

```bash
npm run format
npm run format:check
npm run check
```

Форматирование охватывает документацию в `docs/`, README, инструкции для разработчиков, тесты, CI и конфигурацию npm/Prettier. Оно не переписывает автоматически весь существующий код редактора.

Если менялся Rust:

```bash
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

Для UI и нативных операций пройдите соответствующие пункты [ручного сценария](docs/testing.md#ручная-проверка). В описании PR укажите проблему, новое поведение и выполненные проверки. Не объявляйте тесты или платформы проверенными, если они не запускались.

## CI

[Workflow](.github/workflows/ci.yml) работает на push и pull request с Node.js 22. Он проверяет воспроизводимую установку, оформление, тесты и production-сборку веб-версии. Rust и установщики в этот workflow не входят.
