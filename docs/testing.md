## Команды

Выполняйте из корня репозитория после `npm ci` на Node.js 22+.

| Команда                   | Проверка                                                                     |
| ------------------------- | ---------------------------------------------------------------------------- |
| `npm test`                | Все `tests/*.test.ts`                                                        |
| `npm run test:regression` | Документ, история, буфер, команды, локальные копии, логика, геометрия холста |
| `npm run test:preview`    | Геометрия preview, встраивание ресурсов, открытие окна, масштаб шейдеров     |
| `npm run test:rendering`  | SSR-разметка, жизненный цикл анимаций и расчёты WebGL с тестовым контекстом  |
| `npm run test:containers` | PWB/ZIP, повреждение данных, совместимость и состав HTML/React-пакетов       |
| `npm run typecheck`       | TypeScript без генерации файлов                                              |
| `npm run build`           | TypeScript и production-сборка Vite                                          |
| `npm run check`           | Все тесты и production-сборка                                                |
| `npm run format:check`    | Оформление документации, тестов и CI                                         |

Можно выбрать несколько наборов: `npm test -- preview containers`. Неизвестное имя завершает запуск с ошибкой. Тесты не требуют файла проекта за пределами репозитория: пример старого PWB хранится в `tests/fixtures/legacy-0.4.pwb`.

Для Rust:

```bash
cargo fmt --manifest-path src-tauri/Cargo.toml --check
cargo test --manifest-path src-tauri/Cargo.toml --lib
```

Опция Cargo `--offline` работает только при уже загруженных crates. На Linux нужны системные библиотеки GTK/WebKitGTK, даже для компиляции тестов настольного хоста.

## Как работает запускатель

`tests/run.mjs` обнаруживает наборы, собирает каждый через esbuild с поддержкой импортов `?raw`, затем запускает `node --test` в отдельных процессах. Ненулевой код проверки передаётся вызывающему процессу. Временные файлы создаются в `tests/.run-*` и удаляются в `finally`; при аварийном завершении процесса оставшийся каталог можно удалить вручную.

`tests/support/raw-text.mjs` используется также проверкой минифицированного генератора. `fake-indexeddb` обеспечивает асинхронное хранение снимков. `tests/support/canvas.ts` подменяет PNG-кодирование в проверках файлового сервиса; это не растеризатор и не проверка качества миниатюр.

## Ручная проверка

Автоматические сценарии не заменяют проверку интерфейса и целевой ОС.

1. Создайте пустой проект и проект из шаблона. Добавьте страницы, слои, фигуры и текст; измените масштаб холста и интерфейса.
2. Выделите несколько объектов, переместите, сгруппируйте, скопируйте и вставьте. Проверьте Undo/Redo и отмену жеста через Escape.
3. Импортируйте изображение, видео и шрифт. Сохраните `.pwb`, закройте и откройте его; сравните ресурсы и геометрию.
4. Экспортируйте HTML и React. Проверьте страницы, ссылки, широкий и узкий экраны, шрифты и внешний вид объектов. Соберите React-пакет отдельно с его зависимостями.
5. Совместите несколько анимаций. Проверьте load/hover/click/scroll, WebGL-эффекты, отсутствие WebGL и настройки движения.
6. Проверьте недавние документы и восстановление после перезапуска. Отдельно проверьте отказ IndexedDB или заполненную квоту.
7. В Tauri проверьте открытие, сохранение, отмену диалогов, preview, папку плагинов и сообщения об ошибках.
8. Соберите и запустите установщик на каждой поддерживаемой целевой ОС.

## CI

[GitHub Actions](../.github/workflows/ci.yml) запускает `npm ci`, `npm run format:check` и `npm run check`. CI проверяет веб-часть на Linux с Node.js 22. Проверки установщиков, GPU, CORS реальных серверов и системных диалогов в него не входят.
