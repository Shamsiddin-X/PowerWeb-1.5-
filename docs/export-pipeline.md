# Общий конвейер экспорта

```text
Project
  → validateProject
  → collectResources
  → buildExportTree
  → optimizeExport
  → HTML или React printer + общий CSS + необязательный JS
  → removeUnusedAssets
  → ZIP
```

`codegen/tree.ts` формирует общее дерево ExportNode: тег, атрибуты, текст/дочерние узлы, стили, мобильные переопределения и события. Геометрия, группы, семантика, преобразование навигации, шейдерные поверхности и анимации определяются один раз. HTML- и React-генераторы печатают это дерево; отдельных реализаций раскладки больше нет.

`codegen/optimizer.ts` — независимый проход очистки только экспортной копии. Он удаляет пустые служебные слои и избыточные значения стилей, объединяет одинаковые стили, оставляет используемые keyframes и шрифты, выносит повторные конфигурации шейдеров в таблицу. Видимые фигуры, изображения и текст не удаляются. `OptimizationReport` возвращает счётчики очистки. После печати `removeUnusedAssets` удаляет извлечённые файлы, на которые итоговые HTML/CSS/JS/JSX не ссылаются. Документ редактора не меняется.

## HTML

```text
index.html
page-2.html …
styles.css
script.js       # только когда нужен
assets/images/
assets/video/
assets/fonts/
README.md
```

Каждая страница — самостоятельный HTML-документ. Обычное действие перехода без условий становится `<a href>`; ссылки между страницами работают без JS. Условные действия и сложные наборы действий сохраняют небольшой модуль поведения.

Заголовки, текст, изображения и видео находятся в исходной разметке. Текст автоматически получает `h1`/`h2`/`p` по размеру и порядку; у большого короткого текста первый заголовок выбирается по положению. Семантический тег можно явно задать в свойствах, в том числе `header`, `nav`, `section`, `article`, `button`, `a`, `h1…h6`. Автоматическая эвристика не понимает смысл текста — для итогового сайта заголовки стоит назначить вручную. Изображения получают `alt`; информативное описание задаётся в свойствах медиа. Пустой `alt` позволяет отметить декоративное изображение. Язык и SEO-описание задаются в свойствах страницы; язык действует на весь сайт.

## Раскладка и анимации

На широком экране сохраняются позиции и порядок наложения, горизонтальная геометрия выражена в `%`, высота и вертикальные координаты — в px, шрифты — через `clamp()` и единицы CSS-контейнера. Сплошного перевода всей страницы в `vw` нет.

По умолчанию на ширине до 768 px включается вертикальная flex-раскладка. Порядок — сверху вниз, затем слева направо; исходный z-index сохраняется для широкого экрана. Явные группы сохраняются и также становятся вертикальными. Медиа и фигуры сохраняют пропорции, текст переносится и получает автоматическую высоту, fixed-элементы остаются fixed. Брейкпоинт 320–1600 px и включение адаптации доступны в настройках страницы. Это базовая мобильная компоновка, а не автоматическое распознавание сеток/секций: сложные декоративные макеты требуют осмысленной группировки или отключения адаптации.

Анимации загрузки, наведения, поддерживаемые браузером scroll timelines и появление страницы выполняются CSS. В браузере без scroll timelines содержимое остаётся видимым без эффекта появления. Нажатия запускают отдельный модуль JS. Вложенные визуальные слои позволяют совмещать transform-анимации. `prefers-reduced-motion` отключает CSS-анимации. У шейдеров сохраняются собственные параметры движения и взаимодействия.

Шейдеры и сложные события — необязательные улучшения. При недоступном WebGL текст, изображение или видео остаются видимыми. Фоновый шейдер остаётся за содержимым слоя. Обычный сайт не требует Zustand, приложения PowerWeb или его UI-runtime.

## React

Экспорт включает `App.jsx`, `main.jsx`, `styles.css`, `index.html`, `package.json`, `vite.config.js` и ресурсы. JSX использует те же классы и дерево, а не отдельную Tailwind-раскладку. Импортированные медиа проходят обработку Vite. Шрифты подключаются через общий CSS `@font-face`. Системные шрифты не копируются автоматически.

В начальном HTML находится статическая разметка содержимого. React подключается через `hydrateRoot`; поведение монтируется только при наличии интерактивных функций и очищается при unmount. Несколько страниц переключаются нативными hash-ссылками и CSS. Для сборки пакета нужны зависимости React/Vite из его package.json; зависимости редактора не нужны.

Runtime печатается из читаемых JS-исходников: `browserRuntime.js`, `clickAnimations.js`, `shaders.js` и общего `utils/shaderRenderer.js`. Сериализация данных не использует строковые замены имён переменных внутри пользовательского текста или GLSL. Неиспользуемые модули не включаются. Временный Preview сохраняет единый HTML с inline-ресурсами; файловый экспорт всегда раздельный.

Автоматические проверки и границы покрытия описаны в [руководстве по тестированию](testing.md). Визуальное совпадение сложных макетов проверяется вручную.
