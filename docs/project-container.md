# Контейнер проекта PWB 2

`.pwb` — обычный ZIP с путями UTF-8. Версия приложения остаётся 1.5.1; версия контейнера — 2.0.0.

```text
project.pwb
├── manifest.json
├── project.json
├── assets/
│   ├── images/
│   ├── video/
│   └── fonts/
├── shaders/
│   └── name-hash.pws
└── preview.png
```

`manifest.json` содержит `signature: "POWERWEB_CONTAINER"`, `formatVersion`, `appVersion`, `projectId`, название, время сохранения ISO, список страниц `{id, name}`, список ресурсов `{path, mime, size, hash, hashAlgorithm}`, список шейдеров `{path, name}` и путь миниатюры. SHA-256 идентифицирует содержимое ресурсов; CRC32 ZIP дополнительно обнаруживает повреждение записей. Хеш не является цифровой подписью и не подтверждает автора файла.

`project.json` содержит модель Project без JSON-обёртки старого формата. Содержимое image/video и источники шрифтов ссылаются на относительные пути `assets/...`. CSS `url(...)` также ссылается на файлы. Шейдер слоя/объекта хранит `{"$ref":"shaders/name-hash.pws"}`; `.pws` содержит `{version: 1, shader: ShaderConfig}`. Файл сохраняет все прикреплённые к документу шейдеры, включая встроенные пресеты, и импортированные шрифты. Глобальная библиотека «Мои» сама по себе не является частью документа: вариант попадает в контейнер после применения к слою или объекту.

При открытии ссылки восстанавливаются в данные редактора. Имена страниц, текст и прочие обычные строки не интерпретируются как пути ресурсов. Проверяются структура документа, геометрия, уникальность ID, поддерживаемая версия, соответствие списка страниц, размеры и контрольные суммы ресурсов. Проверка выполняется до замены открытого документа.

Одинаковые ресурсы одного вида и MIME сохраняются один раз. Перед повторным использованием дополнительно сравниваются байты. Имена файлов очищаются; к ним добавляется префикс хеша. Внешние URL скачиваются при упаковке. Ошибка загрузки останавливает сохранение, чтобы контейнер не создавал видимость переносимого проекта с отсутствующим медиа.

`preview.png` — статическая миниатюра первой страницы до 480×320. На ней не исполняется GLSL; видео показывается заглушкой воспроизведения. Если ограничения изображения мешают PNG-экспорту, создаётся простая миниатюра с названием. Недавние документы используют эту миниатюру.

Новые файлы используют ZIP STORE, без повторного сжатия уже сжатых фото/видео и без новой npm-зависимости. Чтение поддерживает STORE и DEFLATE. В старых настольных WebView без `DecompressionStream('deflate-raw')` используется Rust-команда `read_project_archive`. ZIP64, пароли и многотомные архивы не поддерживаются. Лимиты: 20 000 записей, 1 ГБ распакованных данных, manifest до 4 МиБ, project.json до 32 МиБ. Недопустимые и повторяющиеся пути отклоняются. В памяти на упаковку и восстановление требуется больше места, чем размер исходного медиа.

Старые `.pwb` с сигнатурой `POWERWEB_PROJECT` распознаются как JSON-снимки и проходят прежнюю миграцию. Сохранение такого документа пишет новый ZIP. `parsePWB`/`serializePWB` оставлены как совместимые имена для старых JSON-снимков; сервис файлов использует `createPwbContainer`/`readPwbContainer`.

Локальные копии недавних документов и recovery хранятся в IndexedDB `powerweb.documents.v2`, store `snapshots`. Они не являются файлами `.pwb`. В localStorage хранится только индекс недавних проектов и предпочтения. Доступ к IndexedDB сериализован для записи recovery и недавних документов. Автосохранение выполняется с задержкой 500 мс; закрытие вкладки не гарантирует завершение последней асинхронной записи, поэтому ручное сохранение необходимо.

Основные файлы реализации: `services/projectContainer/`, `utils/zipArchive.ts`, `utils/contentDigest.ts`, `services/fileService.ts`, `services/projectSnapshots.ts`.
